# 下周的葬礼

一款以浏览器调查为核心的悬疑解谜游戏原型。

> **剧透提示：这是公开开发仓库，源码和 docs 含剧情、谜题答案及结局草稿。**
> 只想游玩的玩家请使用游戏网址，不要阅读源码和设定。

- 源码仓库：https://github.com/gongmenglin126/next-week-funeral
- 现有试玩：https://next-week-funeral.gonglin556.chatgpt.site （访问权限由站点分享设置决定）
- 正式人物名：主角 **林知还**，朋友 **周惜**；订单页面目前保留“林** / 周**”脱敏显示。
- 源码和试玩继续同步维护；GitHub Pages 尚未启用。
- [最新决定与交接状态](docs/04-current-decisions-and-handoff.md) 优先于初版蓝图中的冲突内容。

玩家与大学好友已经开始了一场约定多年的旅行。两人因不同的冲突处理方式产生争执：她把玩家暂时的沉默理解成厌恶和抛弃，玩家却在冷静后回来，明确告诉她“我是在生气，不是不要你”。第二天，她借口外出买药，却在途中意外去世。她的电脑留在民宿，玩家从处理剩余订单开始，逐渐发现一个以“生前告别体验”为公开外壳的秘密宗教。好友曾因死亡恐惧，准备让玩家成为自己的“守夜人”；但真正的好结局藏在系统记录之外——那次谈话动摇了她对两人关系的全部误读，她决定终止仪式，只是没能活着完成线上取消。

## 当前版本

当前可玩的第一章已包含：

- 独立的全屏故事序章与电脑入口；
- 可操作的朋友电脑桌面与浏览器入口；
- 自适应浏览器窗口；
- 独立记事本，保存可手动勾选的五项行程清单（不是线索簿）；
- 搜索“泊岸旅行”进入统一旅行平台，五笔订单都在“我的订单”；
- 五种取消交互：直接退款、电子票尾号校验、退款规则确认、票面取消预约、逐人退回程票；
- 订单分类、状态筛选、检索、退款回执和帮助页面；
- 五笔真实取消后，在当前画面立即弹出一次安时接送通知；可从通知中心找回，不转场、不跳时；
- 通知进入独立的双人夜间接送订单，支持查看机构信息与尝试取消；
- 可访问的本地论坛与帖子；
- 浏览历史与下载记录；
- 相册保留晚餐与海岸两张不同照片；回收站有一张走廊裁剪副本，可预览、缩放并恢复到相册；不把恢复副本冒充恢复原图；
- 可输入的模拟搜索；
- 关键词搜索结果与历史快照提示；
- 响应式布局；
- 核心设定、章节蓝图和谜题原则文档。

当前版本完整覆盖“清单 → 搜索旅行平台 → 五笔取消 → 未列出接送”的第一章。记事本勾选不会提前触发剧情，回程只退一张票也不会算完成。跨应用和标签切换保留状态，真实浏览器刷新后从头开始。裁剪副本的恢复状态也只在当前游玩会话保留。

后续宗教调查、反向搜图、地图核验及手机好结局仍是设计/局部页面，尚未接成完整可通关剧情。所有账号、预订和退款均为游戏内模拟，不会访问真实账号或资金。

## 本地运行

需要 Node.js 22.13.0 或更新版本。保留 package-lock.json；不要直接升级依赖后再判断旧版本能否运行。

```bash
npm ci
npm run dev
```

生产构建：

```bash
npm run build
```

现有构建脚本使用 Bash 和 GNU timeout，推荐 Linux / WSL；其他环境可运行 `npx vinext build`。当前构建输出是 Vinext/Worker 应用，不是直接交给 GitHub Pages 的静态目录。迁移到 Pages 需另外增加并验证静态构建流程。

只运行第一章状态机测试（不重复构建）：

```bash
node --experimental-strip-types --test tests/chapter-one.test.mjs
```

覆盖全部120种取消顺序、错误校验、分人退票、重复点击、通知关闭后的可找回状态以及手动记事本标记独立性。

## 当前硬约束

- 主要玩法发生在浏览器，不扩展成大而全的桌面模拟器。
- 不设置自动整理证据的“线索簿”；信息保留在网页、标签页、历史和下载中。
- 搜索只用于验证玩家已发现的关键词，不能成为自动发放线索的唯一入口。
- 宗教分层出现，不能一点进去就看到完整教义。
- “一滴泪的重量，取决于落在谁身上”只属于终章手机备忘录，不出现在宗教材料中。
- 朋友自卑、敏感，但“自卑 / 同性恋”都不是她作恶的原因。
- 她曾经真实地选择过玩家，最终也真实地决定取消。
- 好结局必须由玩家推理证明，不能依靠一句遗书洗白。
